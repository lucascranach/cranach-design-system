# Einbinden

Das Designsystem wird ab dem ersten Release auf zwei Wegen ausgeliefert (ADR 0016). Zur Laufzeit laden Besucher in beiden Fällen nur von lucascranach.org.

## Projekte mit Build

Vite, Eleventy und andere Projekte mit Build installieren das Paket von npmjs.com und bündeln die Dateien:

```sh
npm i @lucascranach/design-system
```

```css
@import "@lucascranach/design-system/cranach.css";
```

## Projekte ohne Build

PHP, Jekyll und reines HTML binden die versionierte Kopie vom eigenen Server ein. Jeder Versionsordner ist unveränderlich und darf dauerhaft gecacht werden.

```html
<link rel="stylesheet" href="/design-system/1.0.0/cranach.css">
```

## Was `cranach.css` enthält

| Teil | Layer |
|---|---|
| Tokens als Custom Properties (per `@import "./tokens.css"`) | `cda.tokens` |
| Schriften IBM Plex Sans (variabel, normal und kursiv) und IBM Plex Mono 400 | – (`@font-face`) |
| Icon-Font „Cranach Symbols“ | – (`@font-face`) |
| Reset | `cda.reset` |
| Grundstyles: Fließtext, Überschriften, Links, Fokus | `cda.base` |
| Komponenten | `cda.components` |
| Hilfsklassen | `cda.utilities` |

Weitere Dateien im Paket:

| Export | Inhalt |
|---|---|
| `@lucascranach/design-system/tokens.css` | nur die Tokens |
| `@lucascranach/design-system/tokens` | Tokens als JS/TS-Objekt, z. B. für three.js oder Mapbox |
| `@lucascranach/design-system/tailwind.css` | Tailwind-4-Theme und Zuordnung der shadcn-Variablen |
| `@lucascranach/design-system/custom-media.css` | Breakpoints als `@custom-media` |

## Reihenfolge und Vorrang

Alle Styles des Designsystems liegen in Cascade Layers:

```css
@layer cda.tokens, cda.reset, cda.base, cda.components, cda.utilities;
```

Styles **ohne** Layer gewinnen immer gegen Styles in einem Layer – unabhängig von der Spezifität. Ein Projekt kann das Designsystem also einbinden, ohne dass sich etwas ändert, und alte Regeln danach Schritt für Schritt entfernen (ADR 0003, ADR 0015).

`cranach.css` **vor** den eigenen Styles einbinden. Projekte, die IBM Plex noch selbst mit dem alten, verschobenen Gewichts-Mapping registrieren (Datei „Light“ als 200 usw.), behalten dann ihre eigenen `@font-face`-Regeln: Bei gleichem Familiennamen und Gewicht gilt die später definierte Regel.

Das Designsystem verwendet kein `!important` und nie `outline: none`.

## Tailwind 4

In Tailwind-Projekten liegt `cda` zwischen `base` und `components`: Die Grundstyles gewinnen gegen Tailwinds Reset, Tailwind-Klassen im Markup gewinnen gegen Komponenten des Designsystems. Die Reihenfolge wird beim ersten Vorkommen eines Layer-Namens festgelegt und muss deshalb **vor** `@import "tailwindcss"` stehen:

```css
@layer theme, base, cda, components, utilities;
@import "tailwindcss";
@import "@lucascranach/design-system/tailwind.css";
```

## Themes

Das helle Theme ist Standard. Das dunkle Theme wird so gewählt (ADR 0007):

| Markup | Wirkung |
|---|---|
| `<html data-theme="light">` | erzwingt hell |
| `<html data-theme="dark">` | erzwingt dunkel |
| `<html class="dark">` | dunkel (Konvention von shadcn und cranach-timeline) |
| kein Attribut | folgt der Systemeinstellung `prefers-color-scheme` |

Komponenten verwenden nur semantische Tokens wie `--cda-color-text-default`. Dadurch funktionieren sie in beiden Themes ohne eigene Regeln.

## Tokens verwenden

```css
.teaser {
  padding: var(--cda-space-l);
  color: var(--cda-color-text-default);
  background-color: var(--cda-color-background-subtle);
  border-radius: var(--cda-radius-m);
}
```

Primitive Tokens wie `--cda-color-yellow-500` beschreiben die Palette. In Komponenten und Projekten bitte die semantischen Tokens verwenden, sonst passt das dunkle Theme nicht.
